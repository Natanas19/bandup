## Decisions and boundaries

1. Required text: bands.name, tasks.title, events.title, social_links.platform and events.event_type must contain something beyond ECMAScript trim whitespace. Explicit code points include tabs/newlines, ordinary space, NBSP, BOM and Unicode space separators. U+200B ZERO WIDTH SPACE and U+0085 follow JavaScript trim behavior and are not newly classified as whitespace. Values are tested, never normalized or truncated. Optional descriptions/location remain nullable and unrestricted by this migration.
2. Dates: all eleven timestamptz columns across the five tables must be finite when inserted or effectively changed. Optional due_date/end_at preserve NULL; existing NOT NULL constraints retain SQLSTATE 23502. Existing set_updated_at triggers still replace a supplied audit timestamp on UPDATE; the new guard checks the resulting finite row after those historical triggers, not a discarded incoming value. New audit timestamps supplied on INSERT are checked. No conversion of task deadlines to a date type/noon convention is imposed.
3. Event start: reject INSERT or effectively changed start_at earlier than statement_timestamp(), using the database clock at statement start (not transaction start). Equality is allowed. Unchanged instants, including a different textual timezone offset and existing past/infinite values, do not count as rescheduling. The existing end>=start CHECK remains authoritative. This is validation at statement start, not a promise that the timestamp is still future at commit after lock waits or in long transactions.
4. Slugs: match getPublicProfilePath/isValidPublicSlug: nonblank, no literal C0/DEL controls, not standalone . or .., maximum 2048 UTF-16 code units. Count supplementary Unicode code points as two, preserving emoji compatibility. Unicode, spaces, punctuation, slash and percent signs already accepted by the encoded-path helper remain accepted; no arbitrary kebab-case regex, case folding or trimming. PostgreSQL UTF8 cannot store isolated surrogate code units/NUL, unlike raw JavaScript strings before encodeURIComponent. Slug UNIQUE remains unchanged.
5. Limits: name100, title200, description500/2000, platform/type100, location300 and URL2000 currently appear as HTML maxlength. They do not establish a sufficiently clear new persistence contract, especially UTF-16 versus Unicode scalar counts and legacy edits. They are NOT added as DB restrictions. Only the explicit shared public slug 2048-unit rule is included. Migration 9's separate URL8192-byte ceiling remains unchanged. Resource caps for other fields need a separate approved contract.
6. Legacy preservation is field-by-field: UPDATE compares final NEW/OLD JSONB representations before validation. Unchanged protected values remain editable via other fields. PostgreSQL timestamp serialization includes the actual timezone offset, so equal instants serialize identically within the same statement. Existing NOT NULL/CHECK/FK/ownership/publication rules can still reject an edit independently. INSERT ON CONFLICT validates its INSERT candidate first, so a historical past start or invalid legacy field may be rejected even when its conflict UPDATE would not change that field; use UPDATE for legacy metadata. Supporting a different upsert policy would require an explicit separate contract, not an authorization-bypassing lookup. Historical updated_at auto-updates retain their existing behavior. No blanket NOT VALID CHECK is added because it would still reject unrelated legacy updates.

## Permissions, ordering and concurrency

One SECURITY INVOKER trigger function with empty search_path handles the five table configurations; no new callable helper or application EXECUTE grant is needed. Its own ACL is owner-only, checked after REVOKE on the NEW object. No table/schema/view ACL, membership, RLS policy, owner or authorization rule changes. Five BEFORE INSERT OR UPDATE triggers run after existing BEFORE guards and set_updated_at. The existing URL guard stays earlier than the functional link guard. Earlier authorization failures retain their existing precedence and statement rollback undoes any earlier trigger effects.

Validation uses the actual final locked row and effective OLD/NEW values, not a previous client read. This avoids a read/write gap for field validity but is NOT optimistic concurrency control: valid concurrent edits may still overwrite each other. Migration DDL is transactional, has a five-second lock timeout, and requires an idle authorized migration window; superusers capable of disabling guards remain outside this boundary.
